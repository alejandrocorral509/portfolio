02

UploadHub

A platform to publish, listen to and measure podcasts.

Laravel 12PHP 8.2MySQL138 tests

Code on GitHub ↗

what I did

It was my final project for the web development diploma (May and June 2025), which I programmed myself with Laravel, Blade and Tailwind. In October 2026 I rebuilt almost all of it with an AI agent, Claude Code: I fixed its security flaws and added what turns it into a complete platform.

I decided what to build and in what order, reviewed every change and tested it. To be able to explain every piece, I wrote a chapter-by-chapter guide to the code.

  • Chunked uploads up to 500 MB
  • RSS feed per show
  • Retention curve
  • REST API with tokens
  • Moderation
  • Persistent player

AI ready, still switched off. Transcription with Whisper and summaries and chapters with Claude have their code and tests done, but they're disabled until the APIs are connected.

decisions

  • Audio files are never public on disk.They're served through a route that checks permissions and supports seeking to any point.
  • File type comes from the content.Never from what the browser says.
  • Heavy work goes to a queue.The episode is published right away and ffmpeg processes it afterwards.
  • Plays without personal data.Each play is identified by a hash of the user or session.
  • No N+1 queries.A test visits every page and fails if one appears.

03

VeriFactu demo

Invoicing with a chained hash and a tax QR code, following the rules of the Spanish Tax Agency (AEAT).

JavaScriptSHA-256no build

Open the demo ↗ Code

The AEAT's 3 official examples, calculated right now in your browser with my code

calculating…

Change the amount of record 1 and see what happens to the chain.

what it is

VeriFactu is the Spanish Tax Agency's system against invoicing fraud. Every invoice record stores the SHA-256 hash of the previous one, so changing an invoice that's already been issued breaks the chain.

The demo calculates the hash of issue and cancellation records, verifies the chain and generates the QR code with the URL of the AEAT's test environment. It doesn't send anything to the tax office.

how I validated it

The tests reproduce the 3 examples from the AEAT's official document, and the page checks them on startup. The same file runs in the browser and in Node, which is how the tests run. It's the one calculating the block above.

Built with AI assistance.

04

FitTrack

An Android app for workouts, nutrition and hydration.

KotlinJetpack ComposeFirebaseMVVM

Code on GitHub ↗

what I did

It's my final project for the multiplatform development diploma, extended in October 2026 with AI assistance. Workout mode with timer and rest periods, routines with 9 templates, a food diary with the Open Food Facts API, hydration and 7 and 30-day charts. Sign-in with email and with Google.

decisions

  • MVVM with StateFlow.Screens only draw the state; repositories are the only part that talks to Firebase.
  • Calculations as pure functions.Nutrition and streaks, with no Android code, so they can be tested with JUnit.
  • Each user only sees their own data.Firestore's security rules guarantee it.
  • Everything on the free plan.The profile picture is shrunk to 256 px and stored inside the user's document.
